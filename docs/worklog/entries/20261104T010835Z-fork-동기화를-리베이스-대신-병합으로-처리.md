## 배경

2026-11-04에 작업 브랜치를 원본 저장소의 `e51f4fe` 위로 옮기려 했다. 이 브랜치의 앞쪽 커밋은 PR #8로 이미 fork main에 병합되어 있었고, 뒤쪽 커밋 3개만 main에 없었다.

## 문제

리베이스는 충돌 없이 끝났지만 병합된 커밋의 해시까지 바꾸고 PR 병합 커밋 7개를 없앴다. 이 결과를 강제 푸시해 PR을 열면 main에 이미 있는 내용이 다른 해시로 다시 나타나고, 브랜치가 main과 갈라진 채로 남는다.

## 결정과 근거

리베이스 결과는 푸시하지 않고 버렸다. fork main에서 새 브랜치를 만들어 `e51f4fe`를 병합하고 main에 없던 커밋 3개만 체리픽했다. 병합한 이력을 유지하면서 원본 변경을 받을 수 있고, 리뷰할 범위도 동기화 병합과 커밋 3개로 줄어든다. 대가로 이력이 일직선이 아니게 된다.

노트북 커밋이 고친 `08-2.pytorch.ipynb`는 원본에서 `08-2_pytorch.ipynb`로 이름이 바뀌었으나, 체리픽의 이름 변경 감지로 새 이름에 반영되었다.

## 검증

새 브랜치의 트리 해시는 리베이스한 브랜치와 같았다. fork main과 `e51f4fe`는 모두 새 브랜치의 조상이다. 병합과 체리픽 모두 충돌이 없었다.

## 미해결

로컬 `feat/notion-md-pipeline`은 리베이스된 상태로 남아 원격과 갈라져 있다. 변환 파이프라인은 이 트리에서 다시 돌리지 않았다.
