## 1. 모델 선택에 검증 세트가 필요한 이유

- 테스트 정확도가 가장 높은 설정을 고르면, 테스트 데이터를 학습에 직접 쓰지 않았어도 **선택에 참여**한 셈이 된다. 최종 평가의 객관성이 떨어진다.

| 데이터 | 역할 |
|---|---|
| 훈련 세트 | 모델 학습 |
| 검증 세트 | 모델과 하이퍼파라미터 선택 |
| 테스트 세트 | 선택이 끝난 모델의 최종 평가 |

## 2. 두 번의 분할

```
전체 6,497 ─┬─ 테스트 1,300 (20%)      ← 첫 번째 분할: 최종 평가용으로 잠가 둠
            └─ 훈련 5,197 ─┬─ 학습 4,157 (전체의 64%)   ← 두 번째 분할:
                           └─ 검증 1,040 (전체의 16%)     모델 선택용
```

- 두 번째 `test_size=0.2`는 **남은 훈련 데이터의 20%**다. 두 분할은 의미가 다르다.
- 결정 트리를 쓰므로 표준화하지 않는다(이론 ③).

```python
dt = DecisionTreeClassifier(random_state=42)
dt.fit(sub_input, sub_target)   # 훈련 0.9971, 검증 0.8644 → 과대적합 의심
```

- 이제부터 설정을 비교하는 기준은 테스트 점수가 아니라 **검증 점수**다.

## 3. 교차 검증

### 검증 세트 하나의 한계

| 검증 세트를 | 문제 |
|---|---|
| 크게 하면 | 학습에 쓸 데이터가 줄어듦 |
| 작게 하면 | 어떤 샘플이 들어갔는지에 따라 점수가 크게 흔들림 |
| 한 번만 나누면 | 그 한 번의 운에 판단이 좌우됨 |

- 이론 ②에서 검증 세트 24마리로 에포크를 고를 때 한 마리 차이로 점수가 0.04씩 흔들렸던 문제다.

### 5-폴드 교차 검증

1. 테스트 세트를 제외한 훈련 데이터를 5개 **폴드**로 나눈다.
2. 4개 폴드로 학습하고 나머지 1개로 검증한다.
3. 검증 폴드를 바꿔 가며 5번 반복한다.
4. 검증 점수 5개를 평균한다.

- 각 샘플은 검증에 한 번, 학습에 네 번 쓰인다.
- **폴드마다 모델을 새로 학습한다.** 하나의 모델을 이어서 학습하는 것이 아니다. `cross_validate()`에 이미 학습한 `dt`를 넘겨도 그 분할 규칙을 쓰지 않고 설정만 가져가 새로 학습한다.
- **테스트 세트는 교차 검증에 쓰지 않는다.**
- 교차 검증은 성능을 직접 높이는 방법이 아니라, 어떤 설정이 더 좋은지 **판단할 근거**를 주는 방법이다.

### 폴드, 배치, 에포크는 다른 개념이다

| 용어 | 무엇을 나누나 | 언제 쓰나 |
|---|---|---|
| 폴드 | 훈련 데이터를 평가용으로 k등분한 조각 | 설정을 평가·비교할 때 |
| 배치 | 한 번 계수를 수정할 때 쓰는 샘플 묶음 | 경사 하강법으로 학습할 때 |
| 에포크 | 훈련 세트를 한 바퀴 다 쓴 단위 | 경사 하강법으로 학습할 때 |

- 배치와 에포크는 한 모델의 학습 **안**의 단위이고, 폴드는 그 학습을 **바깥에서** k번 반복해 평가하는 단위다.

### cross_validate()

```python
scores = cross_validate(dt, train_input, train_target)
# test_score: [0.8692 0.8462 0.8768 0.8489 0.8354] → 평균 0.8553
```

| 항목 | 의미 |
|---|---|
| `fit_time`, `score_time` | 폴드별 학습·채점 시간 (환경마다 다름) |
| `test_score` | **검증 폴드의 점수**. 처음 떼어 둔 테스트 세트의 점수가 아님 |

### StratifiedKFold

| 설정 | 평균 검증 정확도 |
|---|---|
| 기본값 | 0.8553 |
| `cv=StratifiedKFold()` | 0.8553 (같음) |
| `StratifiedKFold(n_splits=10, shuffle=True, random_state=42)` | 0.8574 |

- 분류 모델의 기본 분할이 섞지 않는 `StratifiedKFold(5)`라서 첫 두 결과가 같다. 회귀 모델은 `KFold`가 기본이다.
- 폴드별 클래스 비율을 원래 데이터와 비슷하게 유지한다.
- 폴드 수가 많다고 점수가 좋아지는 것은 아니다. 학습 횟수가 늘어나므로 평가 안정성과 계산 비용을 함께 본다.

## 4. 실습 A: 교차 검증으로 트리 깊이 고르기

| 최대 깊이 | 평균 훈련 | 평균 검증 | 검증 표준편차 |
|---|---|---|---|
| 1 | 0.7579 | 0.7579 | 0.0004 |
| 2 | 0.8166 | 0.8139 | 0.0104 |
| 3 | 0.8468 | 0.8413 | 0.0052 |
| 4 (A-4) | 0.8609 | 0.8534 | 0.0103 |
| **5** | 0.8697 | **0.8578** | 0.0151 |
| 7 (A-4) | 0.8908 | 0.8553 | 0.0113 |
| 10 | 0.9355 | 0.8538 | 0.0118 |
| 제한 없음 | 0.9975 | 0.8553 | 0.0153 |

- 훈련 정확도 1위는 제한 없음, 검증 정확도 1위는 깊이 5다. 훈련 데이터를 가장 잘 맞힌 모델이 검증에서도 가장 좋지는 않다.
- A-4에서 깊이 4와 7을 추가해도 여전히 깊이 5가 선택됐다.
- 깊이 5를 넘어서면 훈련 점수만 오르고 검증 점수는 0.855 근처에 머문다.
- 깊이 4 이상의 검증 점수는 모두 0.853~0.858 안이다. 이 폭(0.0044)은 깊이 5의 표준편차(0.0151)보다 작다.

### 정답이 아니라 범위를 찾는다 (강의 조언)

- "여기서 찾은 값이 정답이 아닐 수도 있다. 적절하게 부여할 수 있는 하이퍼파라미터 값의 **범위**를 찾는 데 의의를 두어라."
- 이 실험이 알려 주는 것: 깊이 3 이하는 부족하고, 4 이상이면 비슷하다.
- 점수 차이가 변동 폭 안이면 더 단순하고 안정적인 모델(깊이 4: 리프 16개, 표준편차 0.0103)을 고르는 것도 합리적이다("1-표준편차 규칙").

## 5. 하이퍼파라미터 튜닝

| 구분 | 누가 정하나 | 결정 트리의 예 |
|---|---|---|
| 파라미터 | 모델이 데이터에서 학습 | 분할할 특성, 기준값 |
| 하이퍼파라미터 | 모델러가 학습 전에 지정 | `max_depth`, `min_samples_split`, `min_impurity_decrease` |
| 하이퍼파라미터 튜닝 | 여러 설정을 바꿔 보며 검증 성능으로 고르는 과정 | 실습 A, 그리드 서치, 랜덤 서치 |

| 하이퍼파라미터 | 역할 | 복잡도를 줄이려면 |
|---|---|---|
| `max_depth` | 최대 깊이 | 낮춤 |
| `min_samples_split` | 분할하려는 노드의 최소 샘플 수 | 높임 |
| `min_impurity_decrease` | 분할에 필요한 최소 불순도 감소 | 높임 |

$$\frac{N_t}{N} \times (\text{부모 불순도} - \text{자식 가중평균 불순도}) \geq \text{min\_impurity\_decrease}$$

- 정보 이득에 노드의 샘플 비중(N_t / N)을 곱하므로, 아래쪽 작은 노드일수록 분할이 막히기 쉽다.

### 하이퍼파라미터는 서로 영향을 준다

강의 예시: 배치 크기 512에 에포크 1이면 학습이 충분히 되기 전에 끝난다. 와인 학습용 데이터 4,157개 기준:

| 배치 크기 | 에포크 | 총 업데이트 |
|---|---|---|
| 32 | 1 | 130번 |
| 512 | 1 | **9번** → 과소적합 |
| 512 | 15 | 135번 |

- 배치를 키웠다면 에포크나 학습률을 함께 조정해야 한다. 배치 크기 하나만 보고 좋고 나쁨을 판단할 수 없다.
- 결정 트리에서도 `min_samples_split`이나 `min_impurity_decrease`가 먼저 분할을 막으면 `max_depth`는 역할을 하지 않는다(아래 6장 참고).

### 탐색 전략

| 단계 | 방법 | 예 |
|---|---|---|
| ① 한 변수씩 감 잡기 | 나머지는 기본값, 하나만 바꿈 | 실습 A, 단일 그리드 서치 |
| ② 넓게 조합 탐색 | 여러 하이퍼파라미터를 함께, 넓은 범위로 | 다중 그리드 서치, 랜덤 서치 |
| ③ 좋은 영역에서 좁혀 탐색 | ②에서 좋았던 범위 안에서 촘촘하게 | 실무에서 자주 쓰는 coarse-to-fine |

- ①만 하면 상호작용을 놓친다. ②를 처음부터 촘촘하게 하면 조합 수가 폭발한다.

## 6. 그리드 서치 (교안 5장)

### 단일 하이퍼파라미터

```python
params_single = {'min_impurity_decrease': [0.0001, 0.0002, 0.0003, 0.0004, 0.0005]}
gs_single = GridSearchCV(DecisionTreeClassifier(random_state=42), params_single, n_jobs=-1)
gs_single.fit(train_input, train_target)   # 후보 5개 × 5폴드 = 25번 학습 + 최종 재학습 1번
```

- `refit=True`(기본값)이면 선택된 설정으로 **훈련 세트 전체**에 다시 학습해 `best_estimator_`에 저장한다.
- `best_estimator_.score(train_input, train_target)` = 0.9615는 **훈련 정확도**다. 검증 점수나 테스트 점수가 아니다.
- 설정을 고르고 나면 일부를 검증용으로 남겨 둘 필요가 없으므로, 재학습은 훈련 세트 전체로 한다.

### 강의 보충: 모델에 따라 도구와 환경이 바뀐다

| | scikit-learn (지금) | PyTorch 딥러닝 (이후 단원) |
|---|---|---|
| 모델 1개 학습 시간 | 수 밀리초~초 | 수 분~수 시간 (GPU 필요) |
| 탐색 도구 | `GridSearchCV`, `RandomizedSearchCV` | Optuna, Ray Tune 같은 별도 라이브러리, 또는 직접 반복문 |
| 검증 방식 | 교차 검증이 기본 | 비용 때문에 검증 세트 하나를 따로 두는 경우가 많음 |
| 주요 하이퍼파라미터 | `max_depth`, `min_samples_split` 등 | 학습률, 배치 크기, 에포크, 층 수 등 |

- 지금 단계에서 중요한 것은 도구 사용법보다 "학습에는 이런 것이 필요하구나"를 이해하는 것이다. 도구는 환경마다 바뀌지만 원칙(훈련으로 학습, 검증으로 선택, 테스트는 마지막에 한 번)은 같다.

| 속성 | 내용 |
|---|---|
| `best_params_` | 선택된 조합 (`{'min_impurity_decrease': 0.0001}`) |
| `best_score_` | 최고 평균 검증 점수 (0.8682) |
| `best_index_` | 선택된 조합의 위치 |
| `cv_results_` | 모든 후보의 교차 검증 결과 (`mean_test_score`도 검증 폴드 평균) |
| `best_estimator_` | 훈련 세트 전체로 재학습한 모델 |

### 실습 B: 후보별 결과 분석

| min_impurity_decrease | 평균 검증 | 표준편차 | 순위 |
|---|---|---|---|
| 0.0001 | 0.8682 | 0.0092 | 1 |
| 0.0004 | 0.8678 | 0.0113 | 2 |
| 0.0005 | 0.8676 | 0.0106 | 3 |
| 0.0003 | 0.8649 | 0.0087 | 4 |
| 0.0002 | 0.8645 | **0.0084** | 5 |

- 1·2위 차이는 0.0004(0.04%p)로, 표준편차(약 0.01)의 20분의 1 수준이다. 폴드를 다르게 나누면 순위가 바뀔 수 있다.
- B-4: 평균 1위(0.0001)와 표준편차 최소(0.0002)는 다른 후보다.
- 순위가 값의 크기 순서와 상관없이 뒤섞여 있다. 0.0001~0.0005 범위 안에서는 어떤 값을 골라도 큰 차이가 없다.
- 최고점을 찾는 것뿐 아니라 그 선택의 근거가 충분한지도 확인한다. 이 실습은 모델을 더 학습하지 않고 `cv_results_`만 분석했다.
- 강의 강조점: 그리드 서치는 정확한 값 하나를 찾는 도구가 아니라 대략적인 좋은 조합을 찾는 도구다. 그래도 확실히 나쁜 영역을 걸러 내고 범위를 좁히는 데는 효과가 있으므로 최적화 작업은 해 봐야 한다.

### 다중 하이퍼파라미터

```python
params_multi = {
    'min_impurity_decrease': np.arange(0.0001, 0.001, 0.0001),  # 9개
    'max_depth': range(5, 20, 1),                               # 15개
    'min_samples_split': range(2, 100, 10)                      # 10개
}
# 9 × 15 × 10 = 1,350개 조합 × 5폴드 = 6,750번 학습 (로컬에서 약 44초)
```

- 결과: `{'max_depth': 14, 'min_impurity_decrease': 0.0004, 'min_samples_split': 12}`, 평균 검증 0.8684
- `range()`와 `np.arange()`는 종료값을 포함하지 않는다.
- 상위 5개 조합이 모두 0.8684로 동점이었다. 서로 다른 설정이 같은 트리를 만들기 때문이다. 동점이면 후보 목록에서 먼저 나온 조합이 선택된다.

### "깊이 14"는 실제 깊이가 아니다

| 탐색 | 선택된 `max_depth` | 실제 깊이 (`get_depth()`) | 리프 수 |
|---|---|---|---|
| 그리드 서치 | 14 | **10** | 46 |
| 랜덤 서치 | 39 | **12** | 53 |

- 두 모델 모두 `max_depth`에 닿기 전에 `min_impurity_decrease`, `min_samples_leaf`가 성장을 멈췄다. 이 조합에서 `max_depth`는 상한선일 뿐 작동하지 않았다.
- 실습 A의 "깊이 5"(실제로 깊이 5)와 다중 탐색의 "깊이 14"(실제로 깊이 10)를 그대로 비교하면 오해한다.
- 정확한 해석: 다른 설정이 분할을 멈추는 역할을 맡자, `max_depth`는 큰 값이어도 상관없게 됐다. 이것이 하이퍼파라미터 상호작용이다.
- "최적"은 지정한 후보와 교차 검증 조건 안에서의 최고점일 뿐이다.

## 7. 랜덤 서치 (교안 6장)

### 그리드 서치의 탐색량 문제 (강의 경험담)

- BERT 이전 TensorFlow 시절, 모델 하나 학습에 GPU로 2~3시간이 걸렸고 회사 GPU 서버의 메모리도 빠듯했다. 하루에 시험할 수 있는 조합이 몇 개뿐이었다.
- 결정 트리로 44초 걸린 6,750번 학습을, 모델 하나에 2시간 걸리는 딥러닝으로 하면 약 1년 반이 걸린다.
- 하이퍼파라미터 후보를 미리 정해야 한다는 점도 위험하다. 연속값은 어떤 간격으로 나열할지 정하기 어렵다.

| | 그리드 서치 | 랜덤 서치 |
|---|---|---|
| 후보 | 지정한 모든 조합 | 분포·목록에서 무작위 추출 |
| 탐색 횟수 | 조합 수로 결정 | `n_iter`로 지정 |
| 장점 | 빠짐없이 비교 | 계산량을 제한하며 넓게 탐색 |
| 한계 | 후보가 많으면 계산량 폭발 | 좋은 후보를 못 뽑을 수도 있음 |

```python
params_random = {
    'min_impurity_decrease': uniform(0.0001, 0.001),  # 0.0001 이상 0.0011 미만
    'max_depth': randint(20, 50),                      # 20~49
    'min_samples_split': randint(2, 25),               # 2~24
    'min_samples_leaf': randint(1, 25)                 # 1~24
}
rs = RandomizedSearchCV(DecisionTreeClassifier(random_state=42), params_random,
                        n_iter=100, n_jobs=-1, random_state=42)
# 100개 조합 × 5폴드 = 500번 학습 + 최종 재학습 1번
```

- `uniform(loc, scale)`의 두 번째 인수는 상한이 아니라 **구간의 너비**다.
- `randint(a, b)`는 b를 포함하지 않는다.
- `min_samples_split`은 분할하려는 노드의 샘플 수, `min_samples_leaf`는 분할 후 각 자식 노드에 남을 샘플 수를 본다.
- 결과: `{'max_depth': 39, 'min_impurity_decrease': 0.000341, 'min_samples_leaf': 7, 'min_samples_split': 13}`, 평균 검증 0.8695
- 그리드 서치(0.8684)보다 조금 높지만, 탐색 범위와 하이퍼파라미터가 달라서 두 방법의 우열을 비교한 실험이 아니다. 차이(0.0011)도 폴드 간 변동보다 작다.
- `n_iter=100`은 100번 학습이 아니라 조합 100개다.

### min_samples_leaf와 리프 확률

| 설정 | 확인하는 대상 | 랜덤 서치 선택값 |
|---|---|---|
| `min_samples_split` | 분할하려는 현재 노드의 샘플 수 | 13 |
| `min_samples_leaf` | 분할 후 각 자식 노드의 샘플 수 | 7 |

- `min_samples_leaf`는 양쪽 자식 노드에 각각 최소 n개가 남는 분할만 허용한다. 그 결과 모든 리프에 n개 이상의 샘플이 남는다.
- 이론 ③에서 깊이 제한 없는 트리가 테스트 데이터의 99.4%를 확률 1.0으로 예측했던 문제를 완화한다. 리프에 최소 7개가 있으면 확률이 0이나 1로 쏠리기 어렵다.

### 랜덤 서치가 같은 횟수로도 효과적인 이유

- 조합을 9개만 시험할 수 있다면, 그리드 서치(3 × 3)는 각 하이퍼파라미터를 3가지 값으로만 시험한다. 랜덤 서치는 각 하이퍼파라미터를 9가지 값으로 시험한다.
- 성능을 크게 좌우하는 하이퍼파라미터는 몇 개뿐인 경우가 많아서, 그 값을 더 다양하게 시험하는 랜덤 서치가 유리할 수 있다(Bergstra와 Bengio, 2012).

### 실무 전략 (강의 조언)

```
① 랜덤 서치로 넓게 감 잡기 → "이 범위에서 검증 점수가 좋구나"
② 그 범위 안에서 그리드 서치로 촘촘하게 확인
```

- 5장의 탐색 전략(넓게 → 좁게, coarse-to-fine)과 같은 이야기다. 계산 자원이 한정될수록 처음부터 촘촘한 그리드 서치를 하지 않는다.

## 8. 최종 평가 (교안 7장)

```python
dt_final = rs.best_estimator_
dt_final.score(test_input, test_target)   # 0.86
```

| 점수 | 값 | 의미 |
|---|---|---|
| 최고 평균 교차 검증 정확도 | 0.8695 | 후보를 비교할 때 쓴 점수 |
| 최종 테스트 정확도 | 0.86 | 선택한 모델을 별도 데이터로 평가한 점수 |

- 두 점수는 같을 필요가 없고, 테스트 점수가 반드시 더 낮은 것도 아니다.
- 이론 ③에서 같은 테스트 세트를 이미 봤으므로, 이번 테스트 평가는 **교육용 재현**이다.
- 그리드 서치 모델의 테스트 정확도는 0.8615로 조금 더 높았다. 이 숫자를 보고 모델을 바꾸면 테스트 세트가 선택에 참여하게 된다.

- **모델 종류와 하이퍼파라미터를 모두 고르기 전까지 테스트 점수를 보지 않는다.**

### 두 개의 반복: 모델이 학습하는 과정과 사람이 튜닝하는 과정

```
┌─ 바깥 반복: 사람이 튜닝하는 과정 (하이퍼파라미터 탐색) ─────────┐
│  후보 설정 고르기 (max_depth, min_samples_split …)            │
│     ↓                                                       │
│  ┌─ 안쪽 반복: 모델이 학습하는 과정 (fit) ──────────────────┐  │
│  │  데이터로 파라미터 학습                                 │  │
│  │  (트리: 분할 특성과 기준값 / 로지스틱 회귀: 계수와 절편)  │  │
│  └───────────────────────────────────────────────────────┘  │
│     ↓  폴드마다 반복 (교차 검증)                              │
│  평균 검증 점수로 설정 비교 → 다음 후보로                      │
└─────────────────────────────────────────────────────────────┘
        ↓ 설정 확정
   훈련 세트 전체로 재학습 → 테스트 세트에서 한 번 평가
```

| | 모델이 학습하는 과정 | 사람이 튜닝하는 과정 |
|---|---|---|
| 바꾸는 것 | 파라미터 (데이터에서 학습) | 하이퍼파라미터 (사람이 지정) |
| 기준 | 훈련 데이터의 손실·불순도 | 검증 점수 |
| 도구 | `fit()` | 교차 검증, 그리드 서치, 랜덤 서치 |

### 전체 절차

```
테스트 세트 분리 → 훈련 데이터 안에서 교차 검증 → 후보별 검증 점수 비교
→ 설정 선택 → 훈련 세트 전체로 재학습 → 테스트 세트에서 한 번 평가
```

| 개념 | 한 줄 |
|---|---|
| 훈련 / 검증 / 테스트 세트 | 학습 / 선택 / 최종 평가 |
| 교차 검증 | 폴드를 바꿔 가며 새 모델로 k번 평가하고 평균 |
| StratifiedKFold | 폴드별 클래스 비율 유지 |
| 하이퍼파라미터 | 학습 전에 사람이 정하는 조건 |
| 그리드 서치 | 지정한 후보의 모든 조합 |
| 랜덤 서치 | 분포에서 `n_iter`개 조합을 뽑아 탐색 |

## 9. 헷갈리기 쉬운 내용과 정정

| 헷갈리기 쉬운 이해 | 정확한 내용 |
|---|---|
| 폴드 = 배치 = 에포크 비슷한 것 | 폴드는 평가용 분할, 배치·에포크는 학습 과정의 단위 |
| 폴드마다 가장 좋은 조합을 찾음 | 교차 검증은 설정 하나를 평가하고, 탐색이 설정끼리 평균 점수로 비교 |
| 깊이 후보를 검증 데이터로 줌 | 깊이는 비교할 후보 설정이고, 검증 폴드는 채점하는 데이터 |
| `cross_validate`의 `test_score`는 테스트 점수 | 검증 폴드의 점수 |
| `best_estimator_`의 점수 0.9615는 검증 점수 | 훈련 세트 전체에 대한 훈련 정확도 |
| 다중 탐색에서 깊이 14인 트리가 선택됨 | `max_depth` 상한이 14일 뿐, 실제 깊이는 10 |
| 검증 1위가 확실한 최적 | 지정한 후보 안의 최고점. 차이와 변동을 함께 보고, 범위로 해석 |
| 1·2위 차이 0.00004 | 0.0004 (= 0.04%p) |
| `n_iter=100`이면 100번 학습 | 조합 100개 × 5폴드 = 500번 학습, 최종 재학습 1번 별도 |
| 랜덤 서치가 그리드 서치보다 낫다 | 탐색 범위와 하이퍼파라미터가 달라 공정한 비교가 아님. 항상 낫지도 않음 |
