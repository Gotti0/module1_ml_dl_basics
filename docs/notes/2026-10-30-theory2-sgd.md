## 1. 큰 그림: 학습을 이루는 세 요소

| 역할 | 질문 | 이번 단원 | 다른 선택지 |
|---|---|---|---|
| 모델 | 무엇으로 예측하나 | 로지스틱 회귀 (선형식 + 시그모이드) | 선형 SVM, 신경망 |
| 손실 함수 | 얼마나 틀렸나 | 로지스틱 손실 | hinge, MSE |
| 학습 방법 | 어떻게 고치나 | 확률적 경사 하강법 | 미니배치·배치 경사 하강법 |

- 학습할 때 바뀌는 것은 **계수와 절편(파라미터)**뿐이다. 입력 데이터, 정답, 하이퍼파라미터는 바뀌지 않는다.
- `SGDClassifier`는 모델이 아니라 **학습 방법**이다. `loss`를 바꾸면 같은 SGD로 다른 모델을 학습한다.

## 2. 학습 루프 한 바퀴

```
① 점수 계산      z = w·x + b
② 확률 변환      p = σ(z)
③ 손실 계산      L = −log(정답 클래스에 준 확률)
④ 경사 계산      ∂L/∂w = (p − y)·x,  ∂L/∂b = (p − y)
⑤ 파라미터 수정  w ← w − η·∂L/∂w,  b ← b − η·∂L/∂b
→ ①로 돌아가 반복 → 손실이 최소인 w, b
```

| 구분 | 무엇 | 학습 중 바뀌나 |
|---|---|---|
| 데이터 | 입력 특성 x, 정답 y | 안 바뀜 |
| 하이퍼파라미터 | 학습률, 배치 크기, 에포크 수, 손실 함수, 규제 강도 | 안 바뀜 (사람이 정함) |
| 파라미터 | 계수 w, 절편 b | 매번 바뀜 |

## 3. 손실 함수

### 정확도를 손실로 쓰지 않는 이유

| | 정확도 | 로지스틱 손실 |
|---|---|---|
| 보는 것 | 맞았나, 틀렸나 | 정답에 얼마나 높은 확률을 줬나 |
| 0.6으로 맞힘 vs 0.9로 맞힘 | 둘 다 "맞음" | 0.511 vs 0.105 |
| 미분 | 불가능 (띄엄띄엄한 값) | 가능 → 학습에 사용 |

### 로지스틱 손실의 핵심 원리

$$L = -\big[\,y \log p + (1 - y)\log(1 - p)\,\big] = -\log(\text{정답 클래스에 준 확률})$$

- 맞히면 손실이 0에 가깝고, **자신 있게 틀릴수록 무한대로 커진다**.
- 시그모이드와 합쳐 미분하면 경사가 `p − y`로 단순해진다.
- MSE를 시그모이드와 함께 쓰면 크게 틀린 지점에서 경사가 거의 0이 된다. 로지스틱 손실은 크게 틀릴수록 경사가 크다.
- 로지스틱 손실을 최소화하는 것은 **가능도를 최대화**하는 것과 같다. 출력을 확률로 해석하는 근거다.
- 다중 분류에서는 크로스엔트로피 `−log p_정답`으로 확장된다.

### 실습 A-1, A-3: 정답 클래스 확률별 손실

| 정답 클래스 확률 | 로지스틱 손실 |
|---|---|
| 0.99 | 0.010 |
| 0.90 | 0.105 |
| 0.60 | 0.511 |
| 0.10 | 2.303 |
| 0.01 | 4.605 |

- 0.9 → 0.99로 0.09 오르면 손실은 0.095만 줄어든다. 0.1 → 0.01로 0.09 내리면 손실은 2.303 늘어난다.
- 0.01의 손실은 0.99의 약 460배다. 오답을 99% 확신한 예측에 가장 큰 벌점을 준다.

### 문제 유형별 손실 함수

| 문제 | 모델 출력 | 손실 함수 |
|---|---|---|
| 회귀 | 숫자 하나 | 평균 제곱 오차(MSE), 평균 절댓값 오차(MAE) |
| 이진 분류 | 시그모이드 → 확률 1개 | 이진 크로스엔트로피 (= 로지스틱 손실) |
| 다중 분류 | 소프트맥스 → 확률 K개 | 크로스엔트로피 |

- 실무 팁: 손실 함수를 "결과가 좋게 나오는 옵션"으로 고르면 안 된다(예: 회귀에 크로스엔트로피). **문제 유형 → 출력 형태 → 손실 함수** 순서로 정한다.

## 4. 경사 하강법

$$\theta \leftarrow \theta - \eta \cdot \frac{\partial L}{\partial \theta}$$

- **경사**는 수정 **방향**을 정한다. 계수를 조금 바꿨을 때 손실이 어떻게 변하는지(미분값)이고, 그 반대 방향으로 이동한다.
- **학습률 η**는 수정 **크기**를 정한다.
- 목표는 계수를 작게 만드는 것이 아니라 **손실을 작게 만드는 것**이다. 계수는 커질 수도 있다(계수를 작게 유지하는 것은 규제의 역할).
- 목표 지점은 손실이 최소인 곳(기울기 0)이다. 손실이 0인 곳이 아니다.

### 학습률에 따른 차이

예시: 현재 w = 1, 기울기 −2. 가상의 손실 L = (w − 2)²로 계산한 값이다.

| 학습률 | 갱신 후 w | 손실 (갱신 전 1.0) | 결과 |
|---|---|---|---|
| 0.01 | 1.02 | 0.96 | 너무 작음: 거의 안 움직임 |
| 0.1 | 1.2 | 0.64 | 안정적으로 내려감 |
| 0.5 | 2.0 | 0.00 | 이 함수에서만 우연히 한 번에 도달 |
| 1.0 | 3.0 | 1.00 | 최저점을 지나쳐 반대편으로 감 |
| 1.5 | 4.0 | 4.00 | 손실 증가 → 발산 |

- 최저점에 가까워질수록 기울기가 작아지므로, 같은 학습률이어도 보폭이 저절로 줄어든다.

### 지역 최적해

- 로지스틱 손실은 **볼록 함수(그릇 모양)**라서 지역 최적해가 없다. 학습률은 속도와 발산 여부만 좌우한다.
- 지역 최적해를 만드는 것은 학습률이 아니라 손실 함수의 모양이다. 딥러닝처럼 손실이 울퉁불퉁하면 작은 학습률이 웅덩이 탈출을 어렵게 한다. 고차원 신경망에서는 안장점이 더 큰 문제로 꼽힌다.
- 데이터가 완벽히 분리되면 손실이 바닥에 닿지 않고 계수가 끝없이 커진다. 규제가 이를 막는다.

### 실습 B: 한 번의 갱신 (x = 1, y = 1, 초기 w = b = 0)

| 항목 | 학습률 0.1 | 학습률 0.5 (B-5) |
|---|---|---|
| 갱신 전 확률 / 손실 | 0.500 / 0.6931 | 0.500 / 0.6931 |
| 경사 (계수, 절편) | −0.5, −0.5 | −0.5, −0.5 |
| 수정량 | +0.05 | +0.25 (5배) |
| 갱신 후 확률 | 0.525 | 0.6225 |
| 갱신 후 손실 | 0.6444 | 0.4741 |

- 경사는 학습률과 관계없이 같다. 수정량은 학습률에 정비례한다.
- 손실 감소량은 0.049 → 0.219로 약 4.5배다. 손실은 계수에 비선형으로 반응한다.
- 0.4741은 정답 확률이 62.25%가 됐다는 뜻이다(`e^(−손실)`).
- 그래도 "학습률이 크면 좋다"는 결론은 아니다. 샘플 하나, 갱신 한 번이고, 이 샘플의 최저점은 w → ∞ 쪽이라 넘어설 골짜기가 없다.

## 5. 확률적, 미니배치, 배치

**배치 크기**는 계수와 절편을 한 번 수정할 때 쓰는 샘플 수다. 생선 훈련 세트 119마리 기준:

| 방식 | 배치 크기 | 1 에포크당 수정 횟수 |
|---|---|---|
| 확률적 경사 하강법 (SGD) | 1 | 119번 |
| 미니배치 경사 하강법 | 32 | 4번 |
| 배치 경사 하강법 | 119 (전체) | 1번 |

| | 작은 배치 | 큰 배치 |
|---|---|---|
| 경사 | 들쭉날쭉 | 안정적 |
| 메모리 | 적게 씀 | 많이 씀 |
| 학습률 | 작게 잡아야 안전 | 좀 더 키워도 안정적인 경우가 많음 |

- **에포크**는 훈련 세트 전체를 한 번 사용한 단위다. 수정 횟수가 아니다. 1 에포크당 수정 횟수는 `⌈샘플 수 ÷ 배치 크기⌉`이다.
- 다음 에포크는 이전 계수에서 이어서 수정하고, 보통 샘플 순서를 다시 섞는다.
- `SGDClassifier`의 배치 크기는 항상 1이다. `partial_fit`에 119개를 넘겨도 내부에서는 하나씩 119번 수정한다. 배치 크기를 직접 정하는 것은 딥러닝(Keras `batch_size`, 기본값 32)부터다.

## 6. SGDClassifier 코드 (4-2.ipynb)

```python
from sklearn.linear_model import SGDClassifier
sc = SGDClassifier(loss='log_loss', max_iter=10, random_state=42)
sc.fit(train_scaled, train_target)          # 훈련 0.7815, 테스트 0.800 + ConvergenceWarning
sc.partial_fit(train_scaled, train_target)  # 훈련 0.8067, 테스트 0.825
```

| 항목 | 내용 |
|---|---|
| `loss='log_loss'` | 로지스틱 손실. 교재 구판의 `'log'`는 1.1에서 이름이 바뀌었고 1.3에서 삭제됨 |
| `max_iter` | SGDClassifier에서는 **최대 에포크 수**. LogisticRegression에서는 solver의 반복 횟수 |
| `tol` | 손실 개선이 이보다 작으면 자동으로 멈춤. `tol=None`이면 `max_iter`를 정확히 채움 |
| `fit()` | 계수를 초기화하고 처음부터 학습 |
| `partial_fit()` | 현재 계수를 유지한 채 1 에포크 추가 학습 (점진적 학습) |
| `classes=` | `partial_fit`만 쓸 때 **첫 호출에 반드시** 전체 클래스 목록을 넘김 |
| 다중 분류 | OvR 방식: 이진 분류기 7개를 따로 학습. LogisticRegression의 소프트맥스 방식과 다름 |
| 초기값 | 계수와 절편을 0으로 시작 (딥러닝은 작은 무작위 값) |

- **ConvergenceWarning**: `max_iter` 안에 수렴하지 못했다는 신호다. 오류가 아니라 학습이 덜 됐다는 권고다.
- **표준화가 특히 중요하다.** 특성 단위가 크게 다르면 경사 크기도 달라져 하나의 학습률로 맞추기 어렵다.

### 점진적 학습

| 방식 | 방법 | 단점 |
|---|---|---|
| 전체 재학습 | 기존 + 새 데이터로 처음부터 | 데이터가 쌓일수록 느림 |
| 점진적 학습 | 기존 모델 유지, 새 데이터만 추가 학습 | 파국적 망각, 분포 변화에 흔들림, 검증이 어려움 |

- 실무에서는 주기적 전체 재학습을 택하는 경우가 많다.

## 7. 실습 C: 추가 학습하면 계수가 바뀌나

| | C-1 (fit 10 에포크) | +1 에포크 | +1 에포크 더 (C-4) |
|---|---|---|---|
| 계수 변경 | — | True | True |
| 계수 평균 변화량 | — | 2.32 | 1.11 |
| 절편 평균 변화량 | — | 3.71 | 1.22 |
| 훈련 정확도 | 0.7815 | 0.8067 ↑ | 0.7983 ↓ |
| 테스트 정확도 | 0.8000 | 0.8250 ↑ | 0.8250 = |

- 계수 배열은 (7, 5), 절편은 (7,)이다.
- 계수는 두 번 모두 바뀌었지만 **정확도가 항상 오르지는 않는다**. SGD는 정확도가 아니라 손실을 줄이고, 샘플 하나씩 고치므로 점수가 오르내린다.
- 변화량이 줄어드는 것은 기본 학습률 방식이 진행할수록 학습률을 줄이기 때문이다.
- **`.copy()`가 필요한 이유**: `partial_fit()`은 계수 배열을 그 자리에서 고친다. 확인 결과 copy 없이 저장한 변수는 `sc.coef_`와 같은 객체였다. copy하지 않으면 "변화 없음"이라는 틀린 결론이 나온다.

### 모델 학습과 모델 평가

| | 모델 학습 | 모델 평가 |
|---|---|---|
| 하는 일 | 계수·절편 수정 | 고정된 계수로 점수 측정 |
| 메서드 | `fit()`, `partial_fit()` | `score()`, `predict()` |
| 데이터 | 훈련 세트 | 검증 세트 (선택), 테스트 세트 (최종) |

## 8. 에포크와 과대·과소적합

### 손실 곡선과 정확도 곡선

| | 손실 곡선 | 정확도 곡선 |
|---|---|---|
| 값 | 연속값 | 띄엄띄엄한 값 |
| 모양 | 비교적 매끄럽게 감소 | 계단처럼 뛰고 오르내림 |
| 민감도 | 정답 확률이 조금만 올라도 줄어듦 | 0.5 경계를 넘어야만 변함 |

- SGD 점수는 오르내리므로 한 에포크의 값이 아니라 **전체 추세**를 본다.
- 과대적합이 시작되기 전에 학습을 멈추는 것을 **조기 종료**라고 한다.

### 데이터 3분할 (추가 실습 8장)

```
전체 159마리
├─ 훈련 세트 119 ─┬─ 학습용 95  → 계수 학습, 표준화 기준
│                └─ 검증용 24  → 에포크 수 선택
└─ 테스트 세트 40             → 마지막에 단 한 번 평가
```

- 교재 4-2.ipynb는 테스트 점수로 100 에포크를 골랐다. 추가 실습은 이를 검증 세트로 바로잡았다.
- 표준화는 **학습용 데이터에만 `fit`**하고 검증 데이터는 `transform`만 한다. 검증 데이터를 따로 표준화하거나 fit에 넣으면 데이터 누수다.
- `stratify=train_target`으로 검증 세트에도 7종이 비율대로 들어간다.

| 에포크 | 훈련 | 검증 |
|---|---|---|
| 11 | 0.8842 | **0.9583** (최고점) |
| 30 | 0.8105 | 0.8750 |
| 60 | 0.8842 | 0.8750 |
| 100 | 0.9368 | 0.9167 |
| 200 | 0.9579 | 0.9167 |
| 300 | 0.9684 | 0.9167 |

### 최고점(11)이 아니라 100을 고른 이유

1. 검증 세트가 24마리라 한 마리 차이로 0.0417씩 바뀐다. 0.9583과 0.9167은 한 마리 차이다.
2. 11 에포크의 최고점은 한 번 튄 값이다. 30 에포크에서 다시 떨어지고, 훈련 점수가 검증 점수보다 낮아 아직 과소적합 상태다.
3. 100 에포크 이후 검증 점수는 0.9167로 안정되고 훈련 점수만 오른다. 더 학습하면 과대적합 쪽으로 간다.

- 100도 "검증된 최적값"이 아니라 이 데이터에서 합리적인 실습용 선택이다.

### 최종 재학습과 테스트

```python
sc_final = SGDClassifier(loss='log_loss', max_iter=100, tol=None, random_state=42)
sc_final.fit(train_scaled, train_target)   # 학습용 + 검증용 = 훈련 세트 전체
```

- 결과: 훈련 0.958, **테스트 0.925 (40마리 중 37마리)**
- 에포크를 정한 뒤에는 검증 세트까지 합친 훈련 세트 전체로 다시 학습한다.
- 테스트 세트는 여기서 한 번만 쓴다. 이 점수를 보고 다시 튜닝하지 않는다.

## 9. 손실 함수 바꾸기: hinge

| 실험 | 손실 함수 | 훈련 | 비교 대상 |
|---|---|---|---|
| 9-1 (교재 재현) | hinge | 0.9496 | 테스트 0.925 |
| 9-2 | log_loss | 0.9579 | 검증 0.9167 |
| 9-2 | hinge | 0.9368 | 검증 0.9167 |

- hinge는 서포트 벡터 머신의 손실이고 SGDClassifier의 기본값이다.
- hinge는 확률을 만들지 않으므로 `predict_proba()`를 쓸 수 없다.
- 이 데이터의 검증 점수로는 두 손실 함수의 차이가 드러나지 않는다.

## 10. 실무 관점: 개발에서 끝나지 않는다

### 테스트 데이터로 고르면 서비스에서 엉망이 되는 이유

- 테스트 점수로 튜닝하면 테스트 세트가 몰래 검증 세트 역할을 해서 점수가 부풀려진다.
- 데이터가 작으면 우연의 영향이 크다.
- 서비스 데이터는 수집 당시 데이터와 다를 수 있다(분포 변화).

### "이만큼 나온다더니 왜 안 나오냐"

- 테스트 점수는 약속이 아니라 추정이다. 37/40 = 0.925의 95% 신뢰구간(Wilson)은 약 0.80~0.97이다.
- 보고할 때 평가 조건, 범위, 전제를 함께 전달하고 오픈 후 모니터링을 약속한다.

| 원인 | 대응 |
|---|---|
| 작은 표본 | 신뢰구간과 함께 보고 |
| 테스트 점수로 튜닝 | 검증 세트·교차 검증으로 선택 |
| 데이터 누수 | 전처리 `fit`은 학습용 데이터에만 |
| 분포 변화 | 모니터링, 주기적 재학습 |
| 지표 불일치 | 업무 목표에 맞는 지표를 먼저 합의 |

### 모델러의 책임 범위

```
문제 정의 → 데이터 준비 → 학습·검증 → 최종 평가 → 배포 → 모니터링 → 재학습
```

- 배포할 때도 훈련 때 `fit`한 스케일러로 `transform`해야 한다. 모델과 스케일러를 함께 저장한다(`joblib`, `Pipeline`).
- **DevOps**는 개발과 운영의 벽을 허물어 만든 사람이 배포·운영까지 책임지게 하는 문화이자 방법론이다. 개발만 하는 직업이 아니다.
- **MLOps**는 DevOps 원칙을 머신러닝에 적용한 것이다. 코드뿐 아니라 데이터와 모델을 관리하고, 예측 성능과 입력 분포 변화를 모니터링하며 재학습한다.

## 11. 노트에서 바로잡은 내용

| 처음 이해한 내용 | 바로잡은 내용 |
|---|---|
| 손실 함수 종류 중 "평균 오차" | 평균 제곱 오차(MSE) |
| 경사 하강법은 손실이 0인 지점을 찾음 | 손실이 최소(기울기 0)인 지점을 찾음 |
| 데이터를 미분 | 손실 함수를 파라미터에 대해 미분 |
| 점진적 학습에서 은닉 변수가 퇴색 | 예전 학습 내용이 희미해짐(파국적 망각) |
| 작은 학습률 때문에 지역 최적해에 갇힘 | 로지스틱 손실은 볼록해서 지역 최적해가 없음. 갇힘의 원인은 손실 모양 |
| SGDClassifier 계수는 작은 소수 값에서 시작 | 0에서 시작. 작은 무작위 초기화는 딥러닝 |
| 검증 데이터까지 fit | 학습용 데이터에만 fit, 검증 데이터는 transform만 |
| 추가 학습하면 정확도가 오름 | 계수는 바뀌지만 정확도는 내려갈 수도 있음 |
| DevOps는 개발만 하는 직업 | 개발과 운영을 함께 책임지는 문화·역할 |
